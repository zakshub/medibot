# 5. Project Setup Workflow

## 5.1 Startup Flow

Use this order when building out the project:

1. Create the core folder structure
2. Add real source or production files
3. Inventory assets and references
4. Document tools, dependencies, and commands
5. Track status and blockers
6. Update the handoff notes after major changes

## 5.2 Documentation Update Flow

Whenever new work is added:

1. Update `02_Current_Repository_State.md`
2. Update `03_Recommended_Folder_Structure.md` if the structure changes
3. Record progress in `10_Status_Tracker.md`
4. Record meaningful changes in `12_Change_Log.md`

## 5.3 Working Rule

Each major work session should leave behind:

1. Updated status
2. Updated blockers or risks
3. Updated next actions

## 5.4 Completion Rule

A task is not fully complete until the docs reflect what changed.
