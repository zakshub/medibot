# 3. Recommended Folder Structure

## 3.1 Root-Level Structure

Recommended project layout:

1. `DOC/` - project documentation
2. `assets/` - raw and processed media
3. `content/` - scripts, prompts, outlines, captions
4. `src/` - app or automation source files
5. `scripts/` - utilities and helper commands
6. `tests/` - validation and regression checks
7. `output/` - generated deliverables
8. `archive/` - retired files no longer in active use

## 3.2 Suggested `assets/` Breakdown

1. `assets/audio/`
2. `assets/images/`
3. `assets/video/`
4. `assets/reference/`
5. `assets/export/`

## 3.3 Suggested `content/` Breakdown

1. `content/briefs/`
2. `content/scripts/`
3. `content/prompts/`
4. `content/captions/`
5. `content/research/`

## 3.4 Suggested `DOC/` Role

The `DOC/` folder should contain only management and reference material, not working media or code.

## 3.5 Rule

Do not mix raw files, exports, and final deliverables in the same folder. Separation reduces accidental overwrite risk and makes handoff cleaner.
